# RC5 State Model

RC5 introduces purpose-aligned developmental cognition as an inspectable state layer above RC4. It does not execute changes. It observes behavior, evaluates fit against purpose, classifies deficits, selects a minimal acquisition strategy, and prepares governed handoff artifacts.

Core objects:

- `PurposeConstitution`: operator-owned statement of purpose, success dimensions, protected invariants, prohibited behaviors, and change authority.
- `PurposeAlignmentEvaluation`: per-observation assessment of outcome quality, governance, communication, evidence, and efficiency.
- `DeficitHypothesis`: bounded claim about why behavior was weak, with candidate causes and discriminating tests.
- `AcquisitionDecision`: cheapest adequate next step, such as more evidence, a new metric, retrieval change, prompt change, external expertise, or rejection.
- `DevelopmentConsultationPacket`: compact manual external-consultation packet with constraints and omissions.
- `ConsultationResponse`: advisory-only response imported by the operator.
- `UpgradeProposal`: reviewable proposed improvement.
- `ComparativeEvaluation`: baseline versus post-change score for retaining or rejecting an improvement.
- `DevelopmentalLesson`: review-required lesson from an evaluated cycle.
- `RC5Episode`: an ephemeral trace tying the cycle together.

All RC5 objects are serialized as reports. RC5 does not create live execution authority, hidden persistence, provider calls, canonical writes, training, or automatic developmental loops.
