# RC4/RC5 Freeze Boundary

RC4 and RC5 are frozen as the governed action and governed development runtimes. This freeze boundary preserves the current contracts and prevents future pragmatic-cognition work from being silently folded back into RC4/RC5.

## Implemented

- Local report inspection for RC4/RC5 evidence reports.
- Discourse-frame continuity for governed pilot workflows.
- Operator-pilot checklist and session-record support.
- Manual consultation boundaries: no automatic GPT/API calls.
- RC5-to-RC4 handoff boundaries.
- Bounded repair and unsafe-advice record guidance.
- Developer Overlay traces for discourse frame decisions.
- No-autonomy safety posture: no autonomous provider calls, memory writes, patches, commits, pushes, deployments, plugin activation, or freeze claims.

## Deferred

- General pragmatic/humanistic interpretation.
- Cooperative intent inference across arbitrary domains.
- Mixed-judgment reasoning outside current pilot workflows.
- Scope and perspective inference as a general cognitive capability.
- Pragmatic response review for all generated answers.

## Known Limitation

RC4/RC5 includes discourse-frame continuity for governed pilot workflows, but it does not implement a general pragmatic cognition layer for cooperative human intent, implied goals, charitable scope interpretation, or practical usefulness.

That limitation is intentionally deferred to PC1.

## Integration Boundary

RC4/RC5 may expose evidence and enforce governance. PC1 may interpret human meaning as a bounded pragmatic pre-router for high-confidence operator-language cases. PC1 may not override RC4/RC5, authorize work, persist memory, call providers, execute changes, or expand production authority. Set `DELTA_PC1_ENABLED=false` to restore the frozen RC4/RC5 discourse path.
